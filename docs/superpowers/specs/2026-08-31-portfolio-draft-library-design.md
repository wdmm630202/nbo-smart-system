# 南铂线上客片库草稿与发布架构设计

日期：2026-08-31  
状态：设计方向已确认，待用户复核后实施

## 目标

把现有南铂客片网站扩展成可持续增长的线上客片库。现有 158 张客片继续正常在线；用户以后从本机后台上传的新照片先作为本地草稿保存，只有完成主题归类、公开授权确认和预览后，才允许同步到客户网站。

框架可以在没有任何新照片时先部署。空位置、草稿照片和草稿主题不得出现在客户页面。

## 已确认的产品方向

- 继续使用现有 Mac 本机管理台，不建设公网 CMS，不增加账号、密码或云端客片数据库。
- 现有 `NB-001` 至 `NB-158` 保持公开、编号和收藏兼容性不变。
- 新照片从 `NB-159` 开始自动顺序编号，不预先制造空白占位。
- 新上传内容默认是本地草稿，未确认公开前不进入 Git、不进入发布目录、不产生公开 URL。
- 客户网站只读取已公开记录；没有公开客片的新主题不显示。
- 管理流程保持三步：上传和整理 → 本地预览 → 明确确认后同步网站。

## 不采用的方案

### 固定扩容到 500 个空位

实现较快，但会产生大量无图片编号、空主题和无效统计，长期维护容易混乱，因此不采用。

### 公网云端 CMS

可以异地上传，但需要账号权限、云存储、密钥和客户隐私治理。当前单机运营没有必要承担这些成本和风险，因此不在本期范围内。

## 总体架构

系统分为三个边界清晰的层级：

1. **现有公开图库**：继续由 `catalog.js` 管理 158 张历史客片，确保当前页面、编号、收藏和首页轮播不发生迁移风险。
2. **本地草稿库**：新增内容存放在 Git 忽略的本地管理目录，只允许本机管理服务读取，不被 Pages 导出。
3. **公开增量清单**：经过确认的新增照片写入一个公开增量清单，与现有 158 张在浏览器中合并展示。

这样可以先上线能力而不改动现有内容，同时避免一次性重写 158 张历史数据。

## 数据模型

### 本地草稿记录

每张草稿包含：

- 自动分配的稳定编号候选值；
- 原始文件名和本地生成的高清图、缩略图路径；
- 场景、主题、风格分类；
- 状态：`draft`、`ready` 或 `archived`；
- `approvedForPublicUse` 布尔值；
- 创建和最后修改时间。

草稿数据不保存客户姓名、电话、微信或其他个人信息。`approvedForPublicUse` 只记录发布动作已经人工确认，不替代门店自己的授权凭据。

### 公开增量记录

公开记录只包含客户页面所需字段：编号、主题、分类、图片路径、公开时间及首页推荐状态。草稿路径、原文件名和本地操作历史不得进入公开清单。

### 新主题记录

新主题包含主题名称、英文标识、场景、简短描述和封面照片编号。新主题必须至少拥有一张已公开照片并指定有效封面，才能进入客户页面。

## 后台管理体验

现有管理台增加以下功能：

- “新增客片”主操作；
- 单张选择和批量拖入；
- 每张照片的尺寸、比例和格式检查；
- 选择现有主题或创建新主题；
- 明确的“已确认可公开使用”勾选项；
- 草稿、待公开、已公开、已归档四类筛选；
- 本地预览；
- 公开、隐藏和恢复操作；
- 待同步内容汇总和一次确认发布。

后台保持 Apple 式克制层级：状态先于操作、主操作唯一、危险操作不与普通按钮并列、点击即时反馈，不增加促销化装饰和无意义动画。

## 上传与发布流程

1. 用户选择一张或多张照片。
2. 后台逐张检查 JPG/PNG/WebP、最大 50 MB、接近 3:4 且不低于 900×1200。
3. 合格照片在本地生成 1080×1440 高清 JPG 和 480×640 WebP 缩略图，并保留可撤销备份。
4. 用户选择主题、分类并确认公开授权；未完成的照片保持草稿。
5. 用户在本地预览中核对编号、主题、顺序和手机显示。
6. 选择“准备公开”后，系统才把对应资源和公开记录加入源目录。
7. 点击“同步到网站”时，继续执行现有校验、导出、提交、推送和线上版本核对。

批量上传中的单张失败不应丢失其他合格草稿；界面要逐张显示失败原因。

## 可见性规则

- `draft`：仅本地后台可见。
- `ready`：已通过资料检查，但仍仅本地可见。
- `published`：进入公开增量清单和客户网站。
- `archived`：从客户列表隐藏，后台仍可恢复。

“隐藏”用于撤下客户页面展示，不等同于从 Git 历史中彻底删除图片。涉及客户撤回授权或隐私删除时，需要单独执行资产清理流程，后台不得把普通隐藏描述成永久删除。

## 客户页面行为

- 现有 158 张显示、筛选、收藏和编号不变。
- 已公开新增照片与现有照片使用同一套筛选、放大浏览和收藏交互。
- 所有数量都按实际公开照片动态计算。
- 草稿、归档、缺图和无有效主题的记录全部过滤。
- 新照片使用懒加载缩略图；点开大图时才加载高清图。
- 新主题只有满足公开条件后才出现在主题筛选和主题入口中。

## 本地接口边界

管理服务继续只绑定 `127.0.0.1:4174`，沿用随机会话令牌、同源检查和 50 MB 请求限制。新增接口按职责拆分为：

- 读取草稿与公开图库状态；
- 创建和更新草稿；
- 创建草稿主题；
- 将草稿标记为待公开；
- 隐藏或恢复已公开照片；
- 预览和同步。

所有修改接口必须携带当前管理会话令牌。公开网站不包含这些接口，也不能从互联网调用本机后台。

## 发布安全

- 新照片未确认前不得进入 Git 工作区。
- 发布前必须校验照片、增量清单、主题引用和编号唯一性。
- 发现无关文件、非 `main` 分支、远端领先、人工暂存文件或图片包不完整时停止发布。
- 每次发布只提交本次确认的清单与成套图片。
- 导出后检查源目录、`docs/projects/portfolio-v2/` 与固定短链接 `/p/` 一致。
- 推送后同时核对 GitHub Pages 源站和 `p.nanbostudio.com` 的版本号。

## 迁移与部署

第一阶段部署空的公开增量清单、草稿数据结构、后台新增入口和验证逻辑。现有 158 张保持公开，客户页面在没有新增公开照片时应与当前版本视觉一致。

以后用户找到照片后，只需打开本机管理台上传；不需要再次修改网页架构。第一张新照片正式公开时自动使用 `NB-159`，后续编号连续递增。

## 测试要求

- 没有新增照片时，公开网站仍显示恰好 158 张和原有 23 个主题。
- 草稿上传后，发布目录和线上页面都找不到该照片。
- 未勾选公开授权时，不能把草稿标记为待公开。
- 非 3:4、尺寸不足、格式错误和超限文件有明确错误且不会修改图库。
- 新主题没有公开照片或封面时不出现在客户页面。
- 公开后编号唯一，筛选、放大、收藏和直接主题链接正常。
- 隐藏后客户页面不显示，恢复后使用原编号重新出现。
- 批量上传允许部分成功并逐张报告结果。
- 本机接口拒绝跨站请求和缺少会话令牌的修改。
- 全量客片测试、发布目录测试、移动端无横向溢出测试全部通过。

## 非目标

本期不建设远程登录后台、手机公网上传、订单、购物车、在线支付、客户账号、客户资料库、AI 自动分类或永久隐私擦除工具。

## 成功标准

框架上线后，客户当前浏览不受影响；用户可以在 Mac 后台安全新增草稿，无新照片时线上没有空位，找到照片后无需改代码即可完成归类、预览、公开和同步。
